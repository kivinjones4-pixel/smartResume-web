# 数据库设计文档
需包含功能模块：登录认证、基本信息、教育经历、实习经历、工作经历、项目经历、获奖记录、简历整合与导出、AI RAG 向量表等
```text
               ┌───────────────┐
               │     Users     │ (用户账号/登录表)
               └───────┬───────┘
                       │
       ┌───────────────┼───────────────┬───────────────┐
  (1:1)│          (1:N)│          (1:N)│          (1:N)│
       ▼               ▼               ▼               ▼
┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│ UserProfile │ │ Educations  │ │ WorkExps    │ │ ProjectExps │ ... (其他经历池)
└─────────────┘ └─────────────┘ └──────┬──────┘ └──────┬──────┘
                                       │ (M:N)         │ (M:N)
                                       ▼               ▼
                                ┌─────────────────────────────┐
                                │          Resumes            │ (简历主表)
                                └──────────────┬──────────────┘
                                               │ (1:N)
                                               ▼
                                ┌─────────────────────────────┐
                                │      ResumeEmbeddings       │ (AI RAG 向量表)
                                └─────────────────────────────┘
```                    
## 设计要点
* 强约束 (1:1)：user_profiles 加了 UNIQUE 约束，天然限制一个用户只能有一份基本信息。

* 登录邮箱、手机号、用户名等与用户基本信息内的不同。

* 灵活组合 (M:N)：经历记录池与简历主表通过关联表（resume_*_rel）解耦，支持任意复用与二次排序，不污染原始数据。

* 隔离安全 (Multi-Tenancy)：向量表 resume_embeddings 显式维护 user_id 和 resume_id，防止 AI Agent 检索时发生跨租户数据泄露。

* 级联清理 (CASCADE)：删除用户或删除某种经历时，对应的中间关联表和向量索引会自动清理，避免垃圾数据残留
