# 代码规范技能

当编写代码时，遵循以下规范：

## 通用代码规范

1. 代码可读性，非必要不过度优化代码
2. 重要业务/字段/函数注释
3. 复杂函数注释
4. 最佳实践遵循情况
5. 优先复用代码
6. 抽离通用工具代码
7. 不影响原有功能

## 前端
修改前端时读取项目根目录 `docs/structure-reference.md`。页面使用业务 service，底层请求复用 request.ts，保持认证刷新与流式取消行为。

## 后端

- Handler 处理绑定与响应；Service 维护归属、事务及业务规则；避免将数据库逻辑堆入新 Handler。
- 修改经历关联时同时检查 user_id 与 resume_id；涉及多表一致性使用事务，并验证失败路径。
- 配置和日志不包含密钥；模型输出先验证再交给业务使用。

## 验证与规范

复杂行为先读取 `specs/README.md` 与相关变更规范。前端按范围运行 build/lint，后端运行相关包测试；不要为修复局部问题重构无关模块。代码注释说明业务原因与边界，不逐行复述实现。
