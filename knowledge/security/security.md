# 已实现的账号与数据保护

- 账号密码以密码哈希形式保存，接口不会返回密码哈希。
- 登录采用 Access Token 与 Refresh Token 会话机制；Refresh Token 在数据库中以哈希保存，并支持轮换和注销撤销。
- 编辑简历、经历与访问设置的接口需要登录，并按当前用户校验资源归属。
- 平台助手知识检索只使用平台知识库，不会把其他用户的简历作为回答资料。
- 公开简历接口按每份简历的访问权限判断是否允许读取。

# 分享简历时的数据范围

新创建的访问设置默认为私密，AI 问答默认关闭，敏感展示字段默认不勾选。所有者可改为公开或 6 位访客码访问，并可控制真实姓名、生日、电话、邮箱、城市、GitHub 和个人网站是否展示。

访客码模式通过带有效期的签名通行凭证授权，凭证有效 12 小时。访客码不是账号密码：请只发送给预期接收者；怀疑泄露时可先切到私密或公开，再切回受限模式以生成新码。

# AI 数据边界

简历 AI 代理只应依据当前共享简历、允许展示的字段以及所有者主动填写的代理补充信息回答。隐藏字段不会提供给代理。未登录访客的设备标识会先做 SHA-256 哈希再用于每日问答次数统计。

AI 服务需要把相关提示内容发送给系统配置的模型服务来生成回答或润色。当前公开资料没有说明具体模型供应商、跨境处理、保存期限或删除时限，因此 KK 不得对此作保证。

# 用户应注意

- 分享前通过访客页面检查实际显示内容，并只启用必要字段。
- 不要在简历、欢迎语或补充信息中填写密码、API Key、身份证号等秘密。
- 公开链接可能被获得链接的人继续转发；敏感简历优先使用访客码或保持私密。
- AI 输出可能有误，发布或采纳前应核对。

# 无法确认的承诺

当前代码和公开资料不能证明“所有传输及数据库字段均采用高级或多层加密”“定期备份”“固定销毁周期”“仅特定员工可访问”等运营措施。KK 必须避免作出这些未经确认的安全、合规或数据保留承诺。
