# 导入配置设计

状态：draft。

## Context

Go 配置从进程环境读取，Air 独立加载 .env；Windows 用户容易混淆两种入口。数据库和模型请求存在外部副作用，应在配置检查之后执行。

## Decisions

1. 拟为导入入口增加 `-env-file` 与 `-check-config` 参数；默认文件为当前工作目录的 .env，文档要求从 sr-backend 运行。具体参数在实现时与标准 flag 解析统一。
2. 进程中已有非空变量优先；空变量可由文件补充。显式指定文件不存在应失败；默认文件不存在但全部必要进程变量齐全时允许继续。
3. Go 实现选择维护中的 dotenv 解析器或范围明确的解析模块；先验证引号、注释和 BOM 行为，不使用 shell 执行配置。新增依赖需说明价值。
4. check-config 只做配置语法和必填校验，不创建导入记录、不调用模型、不连接数据库。
5. 缺失配置输出变量名；不要输出密钥、完整配置对象或含密码的连接串。

## Alternatives

- 仅写 PowerShell 教程：实现最少，但多终端容易重复出错。技能脚本可以过渡，不作为长期统一入口。
- 整个后端更换配置框架：范围过大，暂不采用。

## Risks 与恢复

- dotenv 解析差异可能改变值：以专门用例覆盖，避免简单拆分被误认为完整 dotenv 规范。
- 错误文件路径：显式路径立即报错，日志仅列路径和错误类别。
- 兼容现有环境注入：保留进程优先，回退时撤销入口改动即可，无数据库迁移。

## 验证

配置解析与优先级使用无网络测试；真实导入使用独立测试库和有效 Embedding 配置，并记录文档/分块数量，不记录密钥。
